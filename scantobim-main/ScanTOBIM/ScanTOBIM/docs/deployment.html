Deployment & Execution Guide

End-to-end reference for deploying the ScanToBIM agentic pipeline — from LiDAR field capture through AI classification, safety gating, Revit element creation, and IFC 4.0 export. Built for industrial and nuclear facility projects.

FastAPI · Python 3.11 IFC 4.0 Export SC1 / SC2 / SC3 Safety Gates HMAC Audit Ledger pyRevit Bridge GPT-4o Classifier

Deployment Architecture

Deployment Modes
Mode 1

On-Premise (Nuclear / Industrial)

Air-gapped or private-network deployment with no external internet dependency except optional OpenAI API. All data stays on corporate infrastructure.

  • Ubuntu 22.04 LTS or Windows Server 2022
  • Python 3.11 in isolated virtualenv
  • SQLite (dev) → PostgreSQL 15 (production)
  • Revit workstation on same LAN or VLAN
  • pyRevit bridge connects via localhost or private IP
  • SFTP server for scan file ingestion
  • Optional: on-premise GPT-4 via Azure Private Endpoint
WHEN TO USE
Nuclear facilities, defense projects, classified environments, facilities with data sovereignty requirements.
Mode 2

Azure Cloud (Engineering Consultancy)

Azure-hosted agent server with hybrid Revit deployment — engineers connect their on-premise Revit workstations via VPN to the Azure-hosted API.

  • Azure App Service (B2/P2) or ACI container
  • Azure Key Vault for HMAC secret and API keys
  • Azure SQL or Cosmos DB for audit ledger
  • Revit on engineer workstations, VPN to Azure VNet
  • Azure Blob Storage for scan files and IFC exports
  • Azure AD authentication (planned)
  • CI/CD via GitHub Actions → Azure deploy
WHEN TO USE
Multi-site engineering consultancies, distributed BIM teams, projects without strict data residency requirements.

Execution Flow

Step-by-Step Execution
1

Scan Capture

Surveyor deploys Leica RTC360 on site, captures 360° point cloud at control point locations. Exports .e57 format (~2–5 GB). Transfers via SFTP or USB to upload workstation.

Field Surveyor 30–120 min on site
2

Session Start

BIM Engineer calls POST /sessions with file path or enables use_synthetic:true for testing. Server returns session_id and initial status. SSE stream available at /sessions/{id}/stream.

BIM Engineer <1 min
3

Quality Gate

Auto-runs immediately: density check (min 50 pts/m²), noise ratio (<15%), point count (>1000). Fails fast if scan quality is insufficient — surveyor is notified to re-scan.

System Auto ~30 sec
4

Coordinate Alignment

Survey control points fed via POST /sessions/{id}/align. Kabsch/SVD rigid transform computed. RMSE validated against 5mm threshold. Fails if alignment is insufficient.

BIM Engineer 2–5 min
5

Segmentation

Open3D DBSCAN clusters point cloud into geometric segments. Bounding boxes computed per cluster. Outliers filtered. Results stored in session database for classification.

System Auto 5–20 min
6

Classification

Rule-based classifier assigns element_type and safety_category. GPT-4o invoked for ambiguous segments (confidence < 0.75). Each classification logged with confidence score.

System Auto 5–15 min
7

Safety Gate Evaluation

SC1 elements hard-blocked — cannot proceed under any circumstance. SC2 elements raise a gate and pause element creation. Teams adaptive card sent to Safety Engineer with full element context.

System Auto <1 min (auto)
8

SC2 Gate Approval

Safety Engineer reviews element details (type, location, bounding box, confidence, classification rationale) in browser or Teams. POSTs approve or reject with optional comment. HMAC signature stamped on decision.

Safety Engineer <5 min per gate
9

Element Creation

Approved elements dispatched to pyRevit bridge JSON API. family_map.json resolves Revit family and type for each element_type. Element placed at computed location and bounding box in model.

System Auto 1–5 min
10

Clash Detection

Runs automatically after all elements created. AABB pairwise intersection check across all new elements. Hard clashes (overlap >0) and soft clashes (clearance <threshold) reported separately.

System Auto <2 min
11

IFC Export

GET /sessions/{id}/export/ifc generates IFC 4.0 file with full Pset_ScanToBIM property sets. Includes source scan reference, classification confidence, safety category, and HMAC audit hash per element.

BIM Engineer ~2 min
12

CDE Upload & Publish

CDE Manager uploads IFC to ACC or BIMcollab. Transitions model state WIP→Shared→Published per ISO 19650 workflow. Audit ledger downloadable as CSV for compliance records.

CDE Manager 5–10 min

Access: REST API · Postman · Revit · Dashboard
Key Actions

  • Handles exceptions rather than routine work

Works from: Office or remote (mobile)
Access: Web browser · Microsoft Teams cards
Key Actions

Quick Start — 3 Deployment Modes

Fastest way to run the agent locally for development and testing. Requires Python 3.11+ on Ubuntu or Windows.
Terminal — Ubuntu / Linux
# Clone and enter project directory
git clone https://github.com/example/scantobim.git ScanToBIM
cd ScanToBIM

# Create virtualenv and install all dependencies
make install       # creates .venv/ with Python 3.11+

# Copy environment template and configure secrets
make env           # copies .env.example → .env
# Edit .env: set AUDIT_HMAC_SECRET, JWT_SECRET, REVIT_BRIDGE_URL

# Start FastAPI server on port 8765
make server        # uvicorn agent.main:app --reload --port 8765

# Verify the server is running
curl http://localhost:8765/health
# → {"status":"ok","version":"0.1.0","db":"connected"}

# Test with synthetic data (no real scan file needed)
curl -X POST http://localhost:8765/sessions \
  -H "Content-Type: application/json" \
  -H "X-API-Key: dev-key-local" \
  -d '{"site_name":"Demo Nuclear Plant","use_synthetic":true}'
# → {"session_id":"sess_abc123","status":"quality_check","...}

# Stream progress via Server-Sent Events
curl -N http://localhost:8765/sessions/sess_abc123/stream

# Run unit tests
make test          # pytest tests/ -v --tb=short

# Lint and type check
make lint          # ruff check .
PowerShell — Windows 10 / 11
# Clone and enter project directory
git clone https://github.com/example/scantobim.git ScanToBIM
cd ScanToBIM

# Create virtualenv and install all dependencies (uses py launcher)
.\make.ps1 install

# Copy environment template and configure secrets
.\make.ps1 env

# Start FastAPI server on port 8765
.\make.ps1 server

# Run tests
.\make.ps1 test

# Build Revit sidecar executable (stb-processor.exe)
.\make.ps1 build-sidecar
NOTE — SYNTHETIC MODE
When use_synthetic:true is set, the server generates procedural point cloud data and simulates all processing steps without requiring a real .e57 file. All safety gates, HMAC signing, and IFC export still execute normally. Ideal for CI/CD pipelines and integration testing.
Containerised deployment for consistent environments and easy orchestration. Supports both local Docker and Kubernetes (Helm chart in /deploy/helm/).
Dockerfile
FROM python:3.11-slim

LABEL org.opencontainers.image.title="ScanToBIM Agent"
LABEL org.opencontainers.image.vendor="ScanToBIM"

WORKDIR /app

# Install system dependencies (Open3D needs libGL)
RUN apt-get update && apt-get install -y \
    libgl1 libglib2.0-0 libgomp1 \
    && rm -rf /var/lib/apt/lists/*

# Copy and install Python dependencies first (layer cache)
COPY pyproject.toml setup.cfg ./
RUN pip install --no-cache-dir -e ".[server]"

# Copy application source
COPY . .

# Create data directories
RUN mkdir -p /scans /data /exports

EXPOSE 8765

# Healthcheck for Docker / k8s liveness probe
HEALTHCHECK --interval=30s --timeout=10s --start-period=20s \
  CMD curl -f http://localhost:8765/health || exit 1

CMD ["uvicorn", "agent.main:app", \
     "--host", "0.0.0.0", \
     "--port", "8765", \
     "--workers", "2"]
Terminal — Build & Run
# Build image
docker build -t scantobim:latest .

# Run with environment variables and scan volume mount
docker run -d \
  --name scantobim-agent \
  -p 8765:8765 \
  -e OPENAI_API_KEY=sk-... \
  -e APPROVAL_SECRET=your-hmac-secret \
  -e REVIT_BRIDGE_URL=http://192.168.1.10:8766 \
  -e TEAMS_WEBHOOK_URL=https://outlook.office.com/... \
  -v /data/scans:/scans \
  -v /data/db:/data \
  -v /data/exports:/exports \
  scantobim:latest

# Check logs
docker logs -f scantobim-agent

# Run with Docker Compose (includes Postgres + pgAdmin)
docker-compose -f deploy/docker-compose.yml up -d

# Scale workers (requires Compose or k8s)
docker-compose up --scale agent=3

# View running containers
docker ps --filter name=scantobim
Production Azure deployment using App Service with Key Vault integration. Revit workstations connect via Azure VPN Gateway to the private VNet.
Azure CLI — Infrastructure Setup
# 1. Create resource group in UK South (adjust region as needed)
az group create \
  --name scantobim-rg \
  --location uksouth

# 2. Create App Service Plan (Linux, B2 = 2 cores 3.5GB RAM)
az appservice plan create \
  --name scantobim-plan \
  --resource-group scantobim-rg \
  --sku B2 \
  --is-linux

# 3. Create Key Vault for secrets
az keyvault create \
  --name scantobim-kv \
  --resource-group scantobim-rg \
  --location uksouth

# 4. Store secrets in Key Vault
az keyvault secret set --vault-name scantobim-kv \
  --name OpenAIAPIKey --value "sk-..."
az keyvault secret set --vault-name scantobim-kv \
  --name ApprovalSecret --value "$(openssl rand -hex 32)"

# 5. Create Web App with Python 3.11 runtime
az webapp create \
  --name scantobim-api \
  --resource-group scantobim-rg \
  --plan scantobim-plan \
  --runtime "PYTHON:3.11"

# 6. Assign managed identity for Key Vault access
az webapp identity assign \
  --name scantobim-api \
  --resource-group scantobim-rg

# 7. Grant Key Vault access to managed identity
IDENTITY_ID=$(az webapp identity show \
  -n scantobim-api -g scantobim-rg \
  --query principalId -o tsv)
az keyvault set-policy \
  --name scantobim-kv \
  --object-id $IDENTITY_ID \
  --secret-permissions get list

# 8. Configure app settings (KV references)
az webapp config appsettings set \
  --name scantobim-api \
  --resource-group scantobim-rg \
  --settings \
  OPENAI_API_KEY="@Microsoft.KeyVault(SecretUri=https://scantobim-kv.vault.azure.net/secrets/OpenAIAPIKey)" \
  APPROVAL_SECRET="@Microsoft.KeyVault(SecretUri=https://scantobim-kv.vault.azure.net/secrets/ApprovalSecret)" \
  SCM_DO_BUILD_DURING_DEPLOYMENT=true \
  WEBSITES_PORT=8765

# 9. Package and deploy application
zip -r dist/scantobim.zip . \
  --exclude ".venv/*" ".git/*" "*.pyc" "__pycache__/*"

az webapp deploy \
  --name scantobim-api \
  --resource-group scantobim-rg \
  --src-path ./dist/scantobim.zip

# 10. Verify deployment
curl https://scantobim-api.azurewebsites.net/health
# → {"status":"ok","version":"0.1.0","db":"connected"}
REVIT WORKSTATION CONNECTIVITY
For the pyRevit bridge to reach Azure, configure an Azure VPN Gateway with point-to-site VPN. Engineers install the VPN client on their Revit workstation. Set REVIT_BRIDGE_URL to the workstation's VPN-assigned private IP (e.g., http://10.10.0.5:8766). The agent server calls the pyRevit bridge inbound — so the Revit machine must have the bridge listener running.

Security & Compliance Notes

Authentication

  • API key header (X-API-Key) on all endpoints
  • Azure AD / Entra ID integration planned (v0.2)
  • HMAC-SHA256 signature on all SC2 approvals
  • Approval tokens are single-use, 24h expiry
  • API keys stored in Key Vault, never in source
  • Rate limiting: 100 req/min per key by default

Network Security

  • TLS 1.3 enforced in all production deployments
  • VPN required for on-premise Revit bridge calls
  • No external network calls except OpenAI API (optional)
  • Azure Private Endpoints for air-gapped GPT-4 access
  • Revit bridge on private VLAN, not internet-exposed
  • SFTP with ED25519 key authentication for scan uploads

Audit & Compliance

  • Every action logged before execution (pre-commit audit)
  • SQLite WAL mode for crash-safe writes on-premise
  • HMAC-chained audit ledger: each entry signs the previous
  • Daily automated backup to Azure Blob or S3
  • ISO 19650 metadata alignment on all IFC exports
  • Pset_ScanToBIM properties: source, confidence, gate decision
  • Audit ledger exportable as signed CSV for regulators
Nuclear & Safety-Critical Facility Notes
For ONR-regulated nuclear facilities, SC1 (safety-critical) elements are permanently hard-blocked — the pipeline will never create them in Revit regardless of any API call or manual override. SC2 elements require a cryptographically signed approval by a qualified Safety Engineer before dispatch to pyRevit. The HMAC audit chain provides a tamper-evident record of every gate decision, classification, and element creation event. The audit ledger is designed to satisfy ONR LC24 (Operating Instructions) and LC28 (Examination, Inspection, Maintenance and Testing) record-keeping requirements.
