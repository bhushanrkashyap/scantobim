What is Scan-to-BIM?

Scan-to-BIM is an enterprise-grade agentic pipeline that ingests raw LiDAR point cloud data from facility scans and automatically classifies, validates, and exports structured Building Information Model (BIM) elements in IFC 4.0 format suitable for direct import into Autodesk Revit and downstream AEC workflows.


The pipeline operates across five deterministic stages — point cloud ingestion via Open3D, geometric segmentation, rule-based and GPT-4o-assisted safety classification, a hard-enforcement Safety Gate (SC1 hard block / SC2 human approval), and finally Revit element creation with IFC export. Every action is recorded to an append-only HMAC-chained SQLite audit ledger before the element is dispatched, ensuring tamper-evidence and full regulatory traceability.

⚠
Safety-Critical Elements (SC1) — structural load-bearing members, fire suppression systems, and life-safety egress paths — are never auto-created. The pipeline raises a SafetyCategoryViolationError and halts immediately. SC2 elements require explicit human approval before dispatch.
Technical Deep Dive

Pipeline Architecture

Five sequential stages process each scan session from raw point cloud through to validated IFC output. The pipeline is orchestrated by agent/orchestrator.py and exposed via FastAPI on port 8765.

Layer Reference

Each stage maps to a specific module in the agent/ package. The pipeline is synchronous within a session and runs as an async FastAPI background task.

Point Cloud Ingestion
agent/tools/scan_tools.py

Loads PLY, PCD, and XYZ formats via Open3D. Generates synthetic nuclear facility data when use_synthetic=true for testing. Outputs a normalized point array with RGB channels.

Python

generate_synthetic(n_points: int = 50_000)
Geometric Segmentation
agent/tools/scan_tools.py

DBSCAN clustering isolates discrete geometry clusters. RANSAC plane fitting extracts floors, walls, and ceilings. Produces a list of labeled segment bounding boxes.

Python
segment_point_cloud(
  pts:  np.ndarray,
  eps:  float = 0.15,
  min_pts: int = 50
) -> List[Segment]
Safety Classifier
agent/classifier.py

Two-pass classification: geometric rule-based heuristics first, then optional GPT-4o enrichment. Assigns SC1, SC2, SC3, or NS to each segment.

Python
classify_segment(
  seg: Segment,
  use_llm: bool = False
) -> ClassifiedElement
Safety Gate
agent/safety_gate.py

Hard enforcement layer. SC1 raises SafetyCategoryViolationError before any DB write. SC2 creates a pending approval record. SC3/NS proceed automatically.

HMAC Audit Ledger
agent/audit.py

Append-only SQLite ledger. Each event carries an HMAC-SHA256 chain hash linking it to the previous record. Audit before action — written before Revit dispatch.

  session_id: str,
  action:     str,

agent/orchestrator.py

Coordinates all five stages for a session. Aggregates results into a SessionResult and triggers IFC export. Runs as an async task behind the FastAPI session endpoint.

Safety Gate & Classification

Every detected element passes through a deterministic safety gate before any Revit action is taken. The gate reads the element's Safety Category (SC1 / SC2 / SC3 / NS) and either hard-blocks, pauses for human approval, or auto-proceeds — then writes an immutable audit event regardless of outcome.

SC1
Hard Block
Never auto-created. Raises SafetyCategoryViolationError. Examples: reactor pressure vessels, primary coolant piping, seismic restraints.
SC2
Approval Required
Pipeline pauses at a named gate. A human approver must call POST /safety-gates/{gate_id}/decide before creation proceeds.
SC3
Auto-Proceed with Audit
Created automatically but every action is recorded in the HMAC-chained audit ledger. Examples: HVAC ductwork, cable trays, support brackets.
NS
Auto-Proceed
Non-safety elements proceed without gate check. Examples: furniture, finishes, architectural cladding, non-structural partitions.

A Session is the top-level unit of work. It tracks the full pipeline from initial scan ingestion through segmentation, classification, safety gating, Revit element creation, and IFC export. Each state transition is recorded in the audit ledger.

IFC 4.0 Export

The pipeline produces a standards-compliant IFC 4.0 file via IfcOpenShell. Every detected element maps to a specific IFC class with appropriate property sets. Safety category metadata is encoded as custom IfcPropertySet entries (pset name: InfraIQ_Safety) so the classification is preserved in downstream BIM tools.

User Guide

This guide walks through a complete pipeline run from uploading a scan to downloading the IFC file. Each step links to the relevant API endpoint and shows what to expect.

1
Upload Scan — or Use Synthetic Data
Point your tool at a .pcd, .las, or .e57 scan file, or set "use_synthetic": true to generate a realistic 125 000-point cloud automatically. Synthetic mode is ideal for demos and CI testing.
2
Check Scan Quality Report
After ingestion the API returns a quality report. Check point_density, coverage_pct, and noise_estimate. If coverage is below 80% consider re-scanning the area. The pipeline will proceed but classification confidence may be lower.
3
Align Coordinate System
The scan is automatically aligned to the site coordinate system using the georef field in the session payload. If you have survey control points, pass them as control_points to enable ICP-based fine alignment. The resulting transform is stored in the session and applied to all IFC geometry.
4
Review Classification Results
Poll GET /sessions/{id} until status is "classifying" or "awaiting_approval". The elements array in the response lists every detected cluster with its assigned IFC class and safety category. Review the classifier confidence scores — anything below 0.75 is flagged for manual review.
5
Approve SC2 Safety Gates
If any SC2 elements were detected, the session pauses at "awaiting_approval". List the open gates with GET /sessions/{id}/safety-gates, then approve or reject each one. Always review the P&ID drawings and the classifier rationale before approving. Rejections are permanent — the element will not be created in this session.
6
Download IFC File
Once status is "complete", call GET /sessions/{id}/export/ifc. The file is standards-compliant IFC 4.0 and can be opened in Revit, ArchiCAD, Navisworks, Solibri, or any IFC-supporting BIM tool. The InfraIQ_Safety property set on every element preserves safety category metadata downstream.

Audit & Compliance

Every significant action — element detected, gate raised, gate decided, element created, export downloaded — is written to an append-only SQLite audit ledger. Events are linked in an HMAC-SHA256 chain: each event's hash is computed over its payload plus the previous event's hash, making any retroactive tampering detectable.

Append-Only Ledger
SQLite WAL mode. Events are only ever inserted — no UPDATE or DELETE is issued. The DB file itself is checksummed on startup to detect file-level tampering.
HMAC-SHA256 Chain
Each event's this_hash is HMAC-SHA256 over json(payload) ‖ prev_hash using a server-side secret key. Chain integrity is verified on every GET /audit request.
Regulatory Alignment
Designed to support nuclear QA requirements (10 CFR 50 App. B, IAEA SSG-39) and general IEC 61508 audit trail requirements for safety-related software.
